# Scheduled ingestion

Consumes the existing shared ops Artifact Registry image. With
`enable_ingest_job = true`, creates a Cloud Run v2 Job, a distinct
`ingest-scheduler` service account, one additive job-scoped `roles/run.invoker`
grant and a weekly OAuth-authenticated Cloud Scheduler trigger.

## Inputs

| Input | Meaning / default |
| --- | --- |
| `project_id`, `env` | Environment project and standard label |
| `region` | Cloud Run region; root also uses this for data |
| `scheduler_region` | Scheduler only; `europe-west1` |
| `runtime_sa_email` | Existing runtime identity from the IAM module |
| `image_tag` | Required explicit unique Docker tag; `latest` rejected |
| `image_repository` | Required shared image path from bootstrap, without tag/digest |
| `image_digest` | Optional `sha256:` plus 64 lowercase hex characters; overrides the tag |
| `enable_ingest_job` | `false`: no resources from this module; enable after publishing the image |
| `application_env` | Required non-secret map, generated by the root from typed variables/module outputs |
| `scheduler_paused` | `true` in this standalone module; root defaults DEV active and TEST/PROD paused |
| `schedule` | `0 6 * * 1`, interpreted in Europe/Madrid (Monday 06:00, following daylight saving time) |
| `task_memory_mib` | `1024`, one vCPU; allowed values 512/1024/2048/4096 |
| `task_timeout_seconds` | `3600`, allowed 60..86400 |
| `task_max_retries` | `0`, allowed 0..1; app already retries transient transfers |
| `deletion_protection` | `true`; root passes its existing protection flag |

All values in `application_env` enter Terraform state. It must never contain
secret payloads, tokens, keys or ADC. `ALERT_SECRET` is the full secret resource
name supplied by the secrets module. The app accesses its latest version with
the Secret Manager API; no `value_source` or secret environment injection is used.
No local impersonation variable is passed: Cloud Run uses its attached runtime SA.
The root passes `SOURCE_BUCKET` and `SOURCE_REGION` (from `app_settings`); the
app derives the regional HTTPS endpoint from them and uses the same values for
Arrow footer reads. `SOURCE_ENDPOINT` is not set by Terraform.

In the locked Google provider 8.7.0, `deletion_protection` exists and defaults
to `true`; the root explicitly passes the same flag as for BigQuery tables.
See the [Registry reference](https://registry.terraform.io/providers/hashicorp/google/8.7.0/docs/resources/cloud_run_v2_job#deletion_protection).

Cloud Run retains the image entrypoint and passes `args = ["run"]` (sync then
build). One task / parallelism one limits tasks within an execution, **not**
concurrent executions. Scheduler calls the asynchronous `:run` API; its success
means launch accepted, not pipeline completed. No automatic Scheduler retries
are configured, but delivery is not an exactly-once guarantee. Serialize manual
runs and scheduled launches; there is no distributed lock.
One optional task retry repeats sync/build: ETag checks and partition replacement
make data loading idempotent, but alerts can be repeated and queries billed again.

## Retention and sizing boundaries

Bootstrap owns the shared `ops-ingest` repository in ops. Tags are immutable.
Its cleanup policy has a single DELETE rule for untagged
versions older than seven days (leftovers from failed pushes). Tagged releases
are intentionally retained and accumulate over time.
See [Google's cleanup limitations](https://docs.cloud.google.com/artifact-registry/docs/repositories/cleanup-policy).

There is no recorded source `HEAD` size/transfer benchmark in the repository.
The initial 1 vCPU / 1 GiB / one-hour limits are estimates based on bounded
8 MiB transfer chunks and at most 16 MiB footer metadata, plus Python/Arrow/SDK
overhead, not on whole-file buffering. BigQuery transforms execute server-side.
Archive size affects transfer duration, not a requirement to allocate the entire
file in RAM. Verify peak memory/duration and adjust after a deliberately scoped
DEV trial; a full 2023-Q3-onwards backfill can exceed the timeout or cost budget.

An unchanged-source run is not free: it still performs metadata/watermark reads,
rebuilds the entire mart and sends a summary. The per-query billing limit is not
a whole-execution spending cap. There is no always-on compute, NAT or VPC
connector in this module.

## Outputs and deployment

Outputs: `image_uri`, `job_name`, `scheduler_job_name`,
`scheduler_sa_email`, `scheduler_paused`, `job_deletion_protection`.
Job-related outputs are null while disabled.

Use the [image-first deployment and verification runbook](../../docs/runbook.md#scheduled-cloud-run-ingestion).
The deployer needs job/schedule management, job IAM get/set and
`iam.serviceAccounts.actAs` on runtime and scheduler accounts. An authorized image
publisher needs repository-scoped Artifact Registry Writer in ops.
Bootstrap ensures DEV/TEST/PROD Cloud Run service agents exist and gives each
`roles/artifactregistry.reader` on that repository. CI apply identities also
receive repository-scoped Reader for deployment checks. The runtime SA receives
no registry role. Use identical `image_repository` and `image_digest` in every
environment to promote one artifact without rebuilding. Google-managed normal
Cloud Run service-agent roles remain prerequisites.

Plan-only provider-mocked tests are in
[ingest_job.tftest.hcl](../../infra/tests/ingest_job.tftest.hcl) and
[ingest_root.tftest.hcl](../../infra/tests/ingest_root.tftest.hcl).
The [root plan guard](../../infra/tests/check-ingest-plan.ps1) checks actual
planned environment settings against root inputs and resource outputs, pause
defaults, API-only secret access and additive IAM. These checks do not verify a
deployment, registry push, Scheduler launch, BigQuery data or Telegram delivery.
